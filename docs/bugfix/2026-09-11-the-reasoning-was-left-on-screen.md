# 模型的推理原文一直留在答案上方

**日期**：2026-09-11 · **发现于**：生产环境端到端复测，镜像 `6bbcc96-221033`，会话 `ses_0105`，招聘方身份
**影响面**：所有身份、所有会话。每一轮结束后，回答上方都留着一段斜体的模型推理原文。
**严重程度**：中。不影响功能，但把不该给终端用户看的内部推理摆在了答案上面，而且内容可能与实际发生的事相矛盾。
**拍板**：2026-09-11，方案「挪进『系统运行详情』」（另外三个候选：不给用户看、结束时清掉、保持现状）。

## 用户看到了什么

回答上方有一段英文斜体：

> The user is asking for the organization chart again, so I need to call that function. …

下面是中文回答。**这一轮一次工具都没调**（代码里唯一的工具调用点 `a.Tools.Call` 之前必然发 `tool_start`，前端步数为 0），所以这段推理说了一件没有发生的事。刷新后这段文字消失——它不落库——所以同一轮刷新前后长得不一样。

## 这是有意设计吗？

**「等待时要让人看到有东西在动」是有意的；「给用户看推理原文」从来没有被决定过。**

| 证据 | 说的是什么 |
|---|---|
| [03-model-and-prompt.md](../03-model-and-prompt.md)（改动前） | 思考开 `display: "summarized"`，因为默认 `omitted` 在聊天界面里是「一段没有解释的长停顿」。**显示的是摘要** |
| 首个提交 `2e93e63` 里的测试 | 断言 `display` 必须是 `summarized`，理由「so the interface can show progress」 |
| [2026-08-28-answers-never-streamed.md](2026-08-28-answers-never-streamed.md) | 修的是「一分钟空白像卡死」；「思考从 2.6 秒起可见」是作为成果写的 |
| `ff28be0`（2026-09-03，改用 Qwen） | 删掉 Anthropic 客户端，**连同上面那条测试**。Qwen 推回来的是 `reasoning_content` 原文，客户端没有摘要模式 |
| [12-qwen.md](../12-qwen.md)（改动前） | 映射表那一行「the interface shows it working」被原样搬过来 |

## 根因

**表层**：前端把推理写进回答上方的 `.thinking` 块，只在重试（`ev.reset`）时清空；正常结束走的 `finalise()` 从不清它。

**深层**：决策的前提——「显示的是摘要」——在换模型供应商时悄悄失效，显示逻辑没变，于是摘要变成了原文。原文是英文、会复述它考虑过但没做的动作、会复述提示词和工具返回的内容。

**制度层**：唯一记录这个前提的测试随供应商一起被删；前端从来没有测试守着「这块显示的是什么」，所以内容变了没有任何东西变红。
**Owner**：`ff28be0` 那次供应商迁移。

**为什么「推理原文」本来也不是好的进度信号**：`clip()` 保留的是**前** 320 个字，一次近一分钟的思考在头几秒后就定格了。真正起作用的进度信号一直是状态栏（正在思考… / 正在查询…）和回答气泡里的打字动画——[styles.css](../../web/static/styles.css) 里 `.typing` 的注释早就写明了这一点。

## 修复

| 改了什么 | 为什么 |
|---|---|
| 删掉回答上方的 `.thinking` 块和它的样式 | 这就是决策本身：推理不出现在回答上方 |
| 推理写进「系统运行详情」，**每次模型调用一行**，插在工具步骤之间 | 抽屉里按实际发生的顺序读：思考 → 它引出的工具 → 看完结果后的思考。`tool_start` 关闭当前行 |
| 推理行**不计入**「N 步」 | N 是既有的步数（工具调用、工具返回、检查结果各算一步）；把「考虑过」计进去，就会出现步数比实际多——正是这次要消除的「说法和事实对不上」 |
| 标题只由 `techSummary()` 一处生成，0 步时写「系统运行详情」 | 原来 `techItem` 和 `finalise` 各拼一份，都不处理 0 步：只有 trace 行的轮次标题是一个光秃秃的 `›`（生产截图里可见）。推理行会让这种轮次变多，所以一起修 |
| 重试时 `dropReasoning()` 删掉失败那次调用的推理行 | 与「失败尝试的文字要撤回」同一个保证；之前成功的调用的行保留 |
| 不再截断，行内 `pre-wrap` 换行 | 抽屉行本身有 260px 上限并可滚动，没有理由只留前 320 字 |

**未改动**：服务端照常把 `thinking` 事件推给浏览器，思考开关与预算不变。**这是已接受的代价**：原文仍会出现在浏览器里，展开抽屉的终端用户仍能看到——拍板时这一点已列出。
